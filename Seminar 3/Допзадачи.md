# Семинар 3. Дополнительные задачи

Все задачи — для самостоятельной работы.
**Все входные данные читаются из консоли. При ошибках ввода программа
должна сигнализировать это и завершаться досрочно.** Код пишем на C, компилируем с
`-Wall -Wextra -Werror`. Отдельно соберите с санитайзерами (флаг `-fsanitize`),
рекомендую попробовать `address`, `undefined`, `memory`.

---

## 01. Проверка судоку

Поле 9 × 9: каждая строка, каждый столбец и каждый квадрат 3 × 3 содержат
цифры 1–9 ровно по разу.

**Ввод:** 9 строк по 9 чисел.

**Вывод:** `VALID` или `INVALID`.

---

## 02. Длинная арифметика

Сложить два числа до 100 цифр; числа читаем как строки.

**Ввод:** две строки — неотрицательные целые числа, каждое длиной до 100 цифр.

**Вывод:** их сумма — тоже как строка.

```
Ввод:  99999999999999999999
       1
Вывод: 100000000000000000000
```

**Подсказка:** В языке C строки — массив `char`.

---

## 03. Матричная алгебра

`transpose`, `mul`, `equal` для матриц 3 × 3; проверить, что `(A · B)ᵀ = Bᵀ · Aᵀ`.

**Ввод:** две матрицы `A` и `B` — по 3 строке из 3 чисел.

**Вывод:** `Aᵀ`, `Bᵀ`, `A · B` и результат проверки равенства.

**Со звёздочкой:** сделать функции для `n × n`. Не используйте VLA.
Посмотрите функции выделения памяти `malloc` и `calloc` (рекомендую последнее).

> **Сноска.** См. задачу 05 — «Матричный калькулятор»: это задача 03 на стероидах.

## 04. Игра «Жизнь»

Поле 10 × 10, `N` поколений.

**Ввод:** 10 строк по 10 символов (`*` — живая клетка, `.` — мёртвая), затем `N`.

**Вывод:** анимация в консоли: каждое поколение рисуется **на одном и том же месте
экрана**, видно ~1 секунду, затем перекрашивается следующее. Прокрутки строками быть
не должно — поле всегда на виду.

**Правила:** у живой клетки с 2 или 3 живыми соседями она выживает, иначе
погибает; у мёртвой клетки ровно 3 живых соседа — она рождается.

**Техника анимации**:
- курсор в начало: `\x1b[H`, очистить экран: `\x1b[2J`;
- задержка: `sleep(1)` или `usleep(...)` из `<unistd.h>` — в стандартном C `sleep`
  нет, это POSIX;
- после каждого кадра `fflush(stdout)`: без него кадр сидит в буфере и анимация
  рассыпается;
- Windows: ANSI-коды надо включить (`SetConsoleMode`,
  `ENABLE_VIRTUAL_TERMINAL_PROCESSING`), иначе `\x1b[H` напечатается как текст.

**Проверка — три узора, их видно в анимации:**

- **block** 2 × 2 — стабильный, поле не меняется: две строки `**` друг под другом.
- **blinker** — три `*` в ряд, период 2: ряд → столбец → ряд.
- **glider** — период 4: на 4-м поколении та же фигура, сдвинутая на клетку
  вниз и вправо. Кадры 0 … 4 (строки 0–4 поля, остальное поле — точки):

```
  0      1      2      3      4
  .....  .....  .....  .....  .....
  .*...  .....  .....  .....  .....
  ..*..  *.*..  ..*..  .*...  ..*..
  ***..  .**..  *.*..  ..**.  ...*.
  .....  .*...  .**..  .**..  .***.
```

Глайдер, как ввод (поле 10 × 10):

```
..........
.*........
..*.......
***.......
..........
..........
..........
..........
..........
..........
4
```

**Со звёздочкой:** размер поля `M × M` читается из ввода — поле выделяем
динамически (`malloc`/`calloc`, `free`), границу проверять по `M`; поле со
«торцевым» краем (координаты по модулю `M`); цветные клетки вместо `*` и `.`
— ANSI-фон (`\x1b[42m` … `\x1b[0m`).

## 05. Матричный калькулятор

Программа работает в цикле и читает команды из консоли. Матрицы динамические:
размер каждой задаётся из ввода, матрица хранится через указатели.

**Команды** — имена матриц однобуквенные (`A` … `Z`), слотов хватает на проверку:

```
read  A 3 4     прочитать матрицу A размера 3 × 4 — следующие 12 целых чисел
write A         напечатать A таблицей
add   A B C     C = A + B
mul   A B C     C = A · B
trans A C       C = Aᵀ
eq    A C       1, если матрицы равны, иначе 0
free  A         освободить A
exit
```

**Ввод:** поток команд; после `read n m` идут `n · m` чисел, разделители —
пробелы и переводы строк в любом сочетании.

**Вывод:** на `write` и `eq` — результат; на команду с несовместимыми размерами
или неизвестную команду — сообщение, цикл продолжается.

**Размеры — часть задачи.** `add` требует одинаковых `n` и `m` у обеих матриц;
`mul` требует `cols(A) == rows(B)`, результат имеет размер `rows(A) × cols(B)`.
`trans` меняет размер, поэтому `trans A A` требует новой памяти и освобождения
старой: матрица, в которую пишем, меняет владельца.

**Проверка — тождество из задачи 03**, только набранное командами:

```
read A 2 3
1 2 3
4 5 6
read B 3 4
1 0 2 1
3 1 0 2
2 3 1 4
mul A B T        T = A · B    (2 × 4)
trans T U        U = Tᵀ       (4 × 2)
trans B V        V = Bᵀ       (4 × 3)
trans A W        W = Aᵀ       (3 × 2)
mul V W X        X = V · W    (4 × 2)
eq U X           1
```

Обе части тождества — матрицы 4 × 2, `mul B A` нельзя: 4 != 2.

> **Сноска.** Это задача 03 на стероидах. Если вы решили эту задачу, задачу 3
> можно не решать.
